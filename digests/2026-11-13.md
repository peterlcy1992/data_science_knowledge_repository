## 🔎 Deep dive: When Both Sides Adapt: The Challenges of Evaluating Interactive LLM Systems

*arXiv stat.ME (Hannah Li) · experimentation-causal (Core DS) · Core-DS pick (rotation: only 1 of the last 4 deep dives was Core DS, so Core DS was due) · novelty 4/5 · full text read*

**The problem.** Teams deciding whether to ship a new LLM lean on two kinds of evidence:
- **Offline benchmarks:** both models answer the same prompts, including replays of historical user prompts.
- **Live A/B tests:** users are randomized to models, and outcomes are measured on what they do next.

Users don't hold still. After seeing an answer they change the task type, the difficulty and how they phrase prompts. So a model partly chooses the prompts it gets judged on. The paper asks whether the two methods measure the same thing and, if not, whether they can disagree about which model is better.

**The example.** 100 users per model start with a routine email request.
- An unusable answer ends the session.
- A generic but usable answer leads to another routine request.
- An excellent answer leads the user to try something difficult.

Both models are 90% usable on routine tasks. The new model M1 is better on difficult ones (70% vs 30% usable) and gives far more excellent routine answers. So M1's users move to hard tasks: about 80 of 90 second-turn requests are difficult, against 10 of 90 for M0. Second-turn success is 72.2% for M1 and 83.3% for M0, and the two-turn average is 81.1% vs 86.65%. Any benchmark that includes some difficult prompts prefers M1; the A/B test prefers M0.

**The framework.**
- **Two estimands.** The *common-distribution effect* compares the models on the same prompt distribution. The *induced-distribution effect* compares each model on the prompts its own users generate. With large samples, the benchmark difference-in-means converges to the first; the A/B test (and user simulation) converges to the second.
- **Decomposition.** The A/B effect = a *performance effect* (the new model on the old model's prompt mix) + a *composition effect* (the change in prompt mix, weighted by the new model's performance on each type of prompt). The rankings reverse only when the composition effect has the opposite sign to the performance effect and is at least as large.
- **A screening rule.** The offline ranking is guaranteed to match the A/B test if |performance effect| ≥ (total-variation shift in prompt mix) × (range of the new model's performance across prompt types). All three quantities can be approximated from offline and historical data before launch. The catch: a coarse grouping of prompts understates the shift, so the paper asks for sensitivity analysis over how prompts are grouped.
- **Side effects of user adaptivity.**
  - *Reward hacking:* a model can raise an aggregate metric by steering users toward easy prompts, without answering any prompt better.
  - *Novelty effects:* if users learned to avoid a task the old model failed at, a model that only improves that task shows roughly zero effect on the old prompt mix. It may also show nothing in a short A/B test until users rediscover the task.
  - *Burn-in:* dropping early turns helps if you want long-run performance, but biases a same-prompt comparison. Decide the estimand first.
- **Variance.** In a stylized linear model, feedback between users and the model makes each user's outcomes an AR(1) process. Variance rises with user adaptivity. When the feedback product γ_P·γ_M is below 1, variance still falls like 1/T but with a larger constant; at 1 it grows linearly in T, and above 1 it grows exponentially. So you need more users for the same power.

**The evidence.** This is a theory paper: propositions plus the worked example, with no empirical LLM study yet.

**Claude's Take (opinion).** This is the clearest statement I've seen of why "the model won the evals but lost the A/B test" happens. The decomposition has the same shape as the mix-shift analyses analysts already run on funnels. What I'd act on:
- Log the mix of task types as a first-class A/B metric.
- Report the performance and composition terms separately.
- Choose the burn-in policy from the estimand, not from habit.

Caveats:
- The agreement bound is worst-case and often won't settle the question.
- It assumes single-turn Markov dependence and no learning across users.
- There is no empirical validation yet.

The CIDER roundtable paper below, which Li co-authored, makes the same point informally.
