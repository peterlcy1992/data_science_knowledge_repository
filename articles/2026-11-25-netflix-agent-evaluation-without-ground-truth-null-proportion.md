# Agent Evaluation Without Ground Truth: A Null Proportion Perspective

**Source:** [Cornell Tech / Netflix (arXiv cs.AI)](https://arxiv.org/abs/2611.31539) · Published 2026-11 · Added 2026-11-25
**Category:** LLMs & Generative AI · **Tags:** `agent-evaluation`, `e-values`, `anytime-valid-inference`, `null-proportion-estimation`, `multiple-testing`, `optional-stopping`, `coding-agents`, `storey-estimator`

## TL;DR

When an agent ships changes whose effect can only be measured with noisy experiments, nobody ever observes whether a given change was "correct". Cho, Lindon and Kallus treat each agent decision as a pair of hypotheses and define agent quality as a weighted count of correct decisions. They then estimate it from sequences of *e-values* instead of labels, borrowing from null-proportion estimation (Storey, Efron). The bounds and confidence sets stay valid under adaptive, dependent decisions, data-driven stopping and quality metrics defined after the fact. In a case study, Claude Opus 5 and Claude Haiku 4.5 each made 50 runtime optimizations to NetworkX. At a 5% minimum-speedup threshold, Opus's estimated *lower* bound on the share of correct changes (≈0.15) sits above Haiku's estimated *upper* bound (0.11).

## 1. Business context

Benchmarks such as SWE-Bench label each decision correct or incorrect with unit tests or reference answers. The paper's motivating case is different: a coding agent changes a user interface to raise average user engagement. Whether a change helped is "a statement about the unknown distribution of the system". You can run an experiment, but the population-level effect is never directly observed. The same holds for science agents that propose hypotheses, run experiments and declare discoveries.

The two common workarounds both fall short here, according to the authors:
- **LLM-as-judge** labels "are prone to substantial bias and invalid confidence intervals", even when fairly accurate (citing Egami et al. 2023).
- **Prediction-powered inference** gives unbiased estimates but needs at least a small set of true labels. This setting has none.

Three features of real agent deployments also break classical null-proportion methods, which assume a fixed set of hypotheses with p-values at a fixed time:
1. Agents act **adaptively**: each decision responds to earlier outcomes, so decisions and evidence can be arbitrarily dependent.
2. Deployments are **monitored continuously** and can be stopped at any data-dependent time, for example after harmful behaviour.
3. Quality may only be **defined after the trajectory ends**. The share of improving changes depends on how many changes were proposed and adopted.

Two of the authors are at Netflix. The paper notes that anytime-valid e-value tests "are already used to gate software releases and to monitor experiments in industrial applications" (citing Lindon et al. 2022 and Johari et al. 2022), so the evidence it needs is often already produced.

## 2. Technical details

- **Estimand.** Agent quality θ* = Σᵢ cᵢθᵢ over the M decisions in a trajectory. θᵢ ∈ {0,1} is the unobserved correctness of decision i. The weights cᵢ may depend on the whole observed trajectory. cᵢ = 1 counts correct decisions; cᵢ = 1/M gives their proportion. Example 1 defines a change as correct if it lifts the goal metric's mean by at least 10% without worsening a guard metric (e.g. crashes). With cᵢ = 1 only for adopted changes, θ* counts "safe improvements".
- **Evidence.** For each decision the analyst observes, over time, a pair of conditional e-values (eᵢ,ₜ, ēᵢ,ₜ). The first tests θᵢ = 1 (large values are evidence the decision was wrong). The second tests θᵢ = 0 (large values are evidence it was right). Observation indicators Rᵢ,ₜ allow evidence to arrive irregularly. The trajectory length N is a stopping time and the number of decisions M is random. Assumption 3 states the e-value property *with θᵢ inside the expectation*, because θᵢ is itself generated by the agent's actions.
- **Upper-bound estimator.** Weighted evidence sums Aᵢ = Σₜ wᵢ,ₜ Rᵢ,ₜ(eᵢ,ₜ − 1) and Āᵢ (same for ē) use nonnegative *predictable* weights, fixed before each new observation. Then ψᵢ = max(cᵢ − Aᵢ, −Āᵢ), and θ̂ᵁ = Σᵢ ψᵢ. A lower-bound class is built analogously (appendix).
- **Validity (Theorem 1).** For any predictable weights meeting an integrability condition, E[θ̂ᵁ − θ*] ≥ 0 uniformly over all trajectory distributions in the class. The bounds are in expectation because two distributions with the same observable law can imply different expected θ*.
- **Sharpness (Theorem 2).** For any observable distribution, some weight sequence brings the estimator's expectation arbitrarily close to the sharpest possible upper bound U(Q̃). The paper's summary: "uniform validity does not come at the cost of instance-wise sharpness."
- **Storey comparison (Lemma 1).** With fixed M and one e-value per decision, convert e-values to p-values (p = min(1, 1/e)) and apply Storey's estimator with threshold λ. Setting wᵢ = λ/(M(1 − λ)) gives an estimator from the new class that is no larger than Storey's, *pathwise*, for every realization. Remark 1 extends this to sequential evidence by first merging each decision's e-values (e.g. their product).
- **Confidence sets (Theorem 3).** For each candidate label vector v ∈ {0,1}ᴹ, a "candidate wealth" Kₜ(v) = 1 + Σᵢ(vᵢAᵢ,ₜ + (1 − vᵢ)Āᵢ,ₜ) drifts downward at the true labels. The set keeps every v with K_N(v) < 1/α and projects to Σcᵢvᵢ. Its endpoints solve a 0–1 knapsack problem, with no solver needed when all cᵢ are equal. Validity needs Assumption 6, **sequential betting with shared wealth**: weights come from betting fractions in [0,1] and transfers from a common wealth pool under a budget constraint. This construction recovers martingale merging (Vovk & Wang) plus weighted-average merging of arbitrarily dependent e-values (Wang 2025) as a special case.
- **Why weights must be shared.** When labels are random, letting each candidate vector have its own weights breaks coverage. Example 3 is an agent reacting to a false alarm: it ships a correct change, sees a spurious alarm with probability 1/10, then ships a bad "fix". With α = 0.1, separate weights miss θ* with probability 0.145. Shared weights of ½ miss it with probability 0.045.
- **Tuning.** Weights are chosen by a predictable heuristic that simulates 64 continuations of the trajectory at each step. For estimation it minimizes or maximizes the bounds' conditional expectation through a pooled LP. For inference it minimizes a convex surrogate of expected width, over a 33-point grid of transfers. Misspecifying the simulator "can affect width, but not validity".

## 3. Impact — potential & realized

**Case study (realized).** Claude Opus 5 and Claude Haiku 4.5, both at high effort, each ran 50 sequential sessions on NetworkX (commit 2622da75c). Each session got the current tree and was asked to make one localized change that reduces runtime and to run the unit tests. Every change built on the agent's earlier ones, so changes were dependent. All 50 sessions finished before any measurement.
- **Measurement.** Each change was timed against its parent tree on fresh random graphs whose seeds the agents never saw, alternating run order. Pairs were kept only if the output checksums matched (none failed). The contrast is the log runtime ratio. A change is correct if the geometric-mean runtime falls by at least p%. Changes spanned 14 workload families, including betweenness centrality, clustering and shortest paths.
- **E-processes.** One-sided right-Haar mixture e-processes on the shifted contrasts (half-normal prior on the standardized effect, scale ½). Sampling stopped once either e-process reached 100 or after 150 pairs, with checks after 10 pairs and every 5 thereafter. The authors argue these are exact e-processes for Gaussian contrasts and *asymptotic* e-processes for non-Gaussian ones with a finite moment above order 2.
- **Results (Figure 1, α = 0.1, cᵢ = 1/M).** Across all thresholds Opus has a higher estimated share of correct changes than Haiku. At 5%, Opus's lower estimated bound is about 0.15 and Haiku's upper estimated bound is 0.11. The 90% pointwise confidence sets' lower ends stay positive even at a 10% threshold for both agents. The paper reads this as evidence that both produce "a nonzero proportion of meaningful improvements".
- The authors call it "a case study, rather than a rigorous evaluation across agents, tasks, and correctness objectives."

**Potential.** Agents can be compared on how often their real-world decisions help, with a correctness threshold set to operational priorities (e.g. "at least a 5% speedup"). The method uses e-values that sequential A/B and release-gating systems already compute. The authors suggest running it over recorded agent trajectories at scale to select agents "in a statistically principled manner". They also note that tighter procedures may be possible under stronger assumptions (i.i.d. e-value pairs, a fixed data-collection policy).

## Claude's Take

> Opinion, not the source's claims.

### Novelty: 4/5 — A clean statistical frame for a question every "autonomous experimentation" pitch skips

The building blocks are known: e-values, game-martingale merging, Storey-style null-proportion bounds, conformal e-prediction. The contribution is to put them together for *agent trajectories*, where labels are random, generated by the agent, and depend on its earlier decisions. The false-alarm example shows this is a genuine change to the problem. Naïve per-hypothesis tuning really does lose coverage. Proving that uniform validity and near-sharpness hold together, and that the class dominates Storey pathwise, makes this more than a reframing.

For data scientists, the important move is to treat agent evaluation as an **experimentation problem, not a labelling problem**. An agent that ships UI changes is a stream of A/B tests with optional stopping. Its quality is "how many of its shipped tests were true wins", which is a false-discovery-style quantity. Teams already running sequential tests (Netflix-style anytime-valid gating) could compute this from logs they have. A natural next step, my guess, would be to compare agent-driven and human-driven experiment programmes on the same footing.

Limits worth keeping in view: the case study has one task, one run per agent and pointwise (not simultaneous) confidence sets across thresholds. Results are shown as a figure, with only the 5% numbers in the text. The NetworkX e-processes are asymptotic, not exact, for non-Gaussian timing noise. The uniform guarantees are deliberately conservative, so intervals may be wide with few decisions. And the weights need a simulator of future trajectories, which adds tuning machinery even if it cannot break validity.

### Jargon buster

- **E-value** — a nonnegative statistic whose expected value is at most 1 if the null is true; big values are evidence against the null. Unlike p-values, they stay valid if you peek and stop early, and averaging them stays valid under any dependence.
- **E-process / anytime-valid** — a running e-value you can check after every observation; a test built on it keeps its error rate whatever stopping rule you use.
- **Null-proportion estimation** — estimating what fraction of many hypotheses are true nulls (here: "decisions that were not correct") without knowing which ones.
- **Predictable weights** — tuning choices made using only data seen before the next observation, which is what keeps the guarantees intact.
- **Shared wealth** — one betting budget for all candidate label vectors instead of a separate one per vector; needed here because the true labels are random and depend on the agent's behaviour.
- **Right-Haar mixture** — a way to build a t-test-like e-process that does not depend on the unknown noise scale.
