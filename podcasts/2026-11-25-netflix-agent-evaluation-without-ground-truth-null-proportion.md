# Netflix — Grading AI agents when nobody knows the right answer

Benchmarks grade coding agents with unit tests, but an agent that ships product changes is graded by noisy experiments, and whether any single change really helped is never observed. Researchers from Cornell Tech and Netflix recast agent evaluation as a multiple-testing problem: each decision becomes a pair of hypotheses, agent quality is a weighted count of correct decisions, and sequences of e-values stand in for the missing labels. We unpack why e-values, unlike p-values, survive peeking, early stopping and arbitrarily dependent decisions; how the upper- and lower-bound estimators stay valid across every possible agent trajectory yet can get arbitrarily close to the sharpest possible bound; why they always beat Storey's classic null-proportion estimator in the simple case; and why a "shared wealth" betting budget is needed once an agent's later moves depend on earlier false alarms. Then the case study: Claude Opus 5 and Claude Haiku 4.5 each propose 50 runtime optimizations to the NetworkX Python library, timed on graphs the agents never saw. At a 5% minimum speedup, Opus's estimated lower bound on the share of correct changes, about 0.15, sits above Haiku's estimated upper bound of 0.11, and both agents' confidence sets stay above zero even at a 10% threshold. We close with what this means for teams that already run sequential A/B tests, and the limits of a single-task case study. Source article: "Agent Evaluation Without Ground Truth: A Null Proportion Perspective" — Cornell Tech / Netflix (arXiv cs.AI; cross-listed stat.ME, stat.AP), https://arxiv.org/abs/2611.31539 (published 2026-11).
